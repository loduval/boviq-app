# Session du 12/10/2026 — réparation de l'import et refonte

Déclencheur : Téo ne pouvait plus importer ses CSV Mil'Klic, et l'import raté
effaçait son historique.

## Trois causes enchaînées
1. `detectType()` n'acceptait que les noms produits par `milklic-sync.py`.
   Mil'Klic livre `gvResultats.csv`, `ASPxGridView*.csv` : tout import manuel
   échouait. → détection sur préfixe, nom natif, puis en-têtes (25 cas testés).
2. `handleFiles()` vidait `ML` avant de parser et appelait `saveML()` même sans
   aucun fichier reconnu. → fusion dans l'existant, restauration si échec total.
3. Le module Mil'Klic n'avait jamais eu de jeton (`REMPLACER_PAR_TOKEN_GH`) :
   `data/milklic-live.json` était figé au 21/03. → jeton partagé avec V6.

## Pièges de données corrigés
- V6 `load()` : repli silencieux sur `INIT_DATA` + saisie = écrasement de la
  production. → `MODE_DEGRADE`, écriture refusée, bandeau, cache local.
- V6 : conflit d'écriture détecté par empreinte git (`gitBlobSha`).
- Mil'Klic `ghLoad()` : « absent » et « panne réseau » confondus, le jeu
  d'amorçage écrasait les données réelles. → `{etat:'ok'|'absent'|'erreur'}`.

  C'était la cause des `?v=N`. Sur Vercel, `vercel.json` fonctionne.
- Historiques lait / TB / TP : en-têtes strictement identiques, indétectables
  par contenu. Le nom du fichier est le seul discriminant.
- Le nom de cache du service worker doit changer à chaque mise en ligne.
- Avant toute modification : `python3 scripts/audit-boviq.py` puis extraction
  des blocs `<script>` et `node --check`.
